FM/MIDI monitor

The FM/MIDI monitor is the old MIDI part table and the old FM keyboard, in one window. Both kinds of music do not play at once, so the window swaps to match whatever is sounding. On MIDI it watches the SMF (.mid / .midi / .kar / .rmi) as 32 parts (A01–A16 / B01–B16). Where the piano roll shows notes over time, the MIDI side lists each part's tone, level, and effects.

MIDI monitor

How to open it

  • Always-on FM/MIDI button between VST and CD on the media-player bottom bar (stays depressed while open; the narrow label is F/M)
  • Media-player banner right-click → Window → MIDI monitor…
  • Playlist right-click → Window → Open MIDI monitor
  • Seeing notes on the piano roll / analyzer / EQ right-click → Open → MIDI monitor
  • VST host wiring canvas right-click → Open MIDI monitor
  • Command palette: “MIDI monitor” or “FM monitor”
Tip

Position and size are remembered. FM and MIDI are not two windows.

Switching between FM and MIDI

The caption is FM/MIDI monitor. Only one side is showing, chosen from what is playing.

  • MIDI — SMF, Playing .mid through a VST, the VST host keyboard, and CEmu MIDI output. The 32-part table.
  • FM — SASAMI .fpy, PMD, FMP, and Bonus: old-machine sound chips such as OPN, OPNA, OPM, and OPL. Keys and registers.
  • Before anything is playing, the window starts on the MIDI table. After you stop an FM track, the next open stays on FM.

What the FM side shows

The FM side changes its shell to match the chip. OPNA (YM2608) is 6 FM channels, SSG, rhythm, and ADPCM. OPN (YM2203) is mainly 3 FM channels, and the lower rows stay empty. OPM, OPL, and arcade PCM use that chip's keys and panels.

  • The header names the chip and whether you are looking at keys, registers, or both.
  • The middle is hex registers and a panel per channel (algorithm and levels).
  • The bottom is the channel keyboard. Held notes light up.
  • PMD and FMP show registers and keys. If FMP cannot supply registers, only the keys remain.
  • An old fmpmd.kpi by itself will not drive PMD or FMP. A newer Plugins pack is swapped in quietly at startup. The KPI download in Rendering settings fetches the same pack.

CEmu dumps and SASAMI dumps are kept apart. The first uses the temp folder ogg_cemu; the second uses ogg_kbsasami.

Header

  • BPM, tempo %, key, time base, meter, transpose, file name (sequence name beside it when present; a name that is only "???" is omitted)
  • DS volume %, note count, DRUM
  • To the right of DRUM: current bar/total (001/051), beat/beats-in-the-bar (1/4→2/4→3/4→4/4), tick-in-bar / ticks-per-bar (0000/1920). They follow the play position. If the meter changes, the beat denominator follows it.
  • Reverb / chorus / variation (XG TYPE MSB/LSB. GS Variation column is the Delay macro 40 01 50; Rev/Cho from 40 01 30/38. Before a song message, the reset default of that mode)
  • SYS (GM / GS / XG), INSERTION (names from the song SysEx: Thru, Distortion, Stereo-EQ… — XG Insertion 1–4, Variation used as insertion, or GS/88Pro EFX)
  • Under B16: INSERTION details (two rows, or four when INS3/4 is used). Connected parts, active parameters (Drive, EQ gains…), EFX sends to Rev/Cho/Delay. Manual names, not hex (res/insertion.dat)

How SysEx is read

Values come from the SysEx written in the song. GS DT1 is Roland F0 41 dv 42 12 and Korg NS5R/NX5R-compatible F0 42 3n 42 12. Part 1x covers bank / program / Rx channel / rhythm plus key shift, level, pan, and chorus / reverb / delay send. 2x is vibrato, TVF (cutoff / resonance), and TVA (attack / decay / release). 4x address 22 is EFX ON. System 40 01 includes Delay (address 50) as well as Reverb / Chorus. XG Multi Part 08 (A01–A16) and 09 (B01–B16) cover bank, PC, Part Mode, volume, pan, sends, vibrato, filter, and EG. EQ frequency becomes Hz only for table index 0–15. Insertion is 03 00–03 (MU100 03 10 = INS2). SD-90 GS dumps use the same DT1; tone names also use native bank MSB.

The 32-row channel table

Each row is one part. The top 16 rows are the first half; the bottom 16 are the second. Drums follow the song (channel 10 is not always drums). During VST playback, GS Reset is followed by rhythm mode on A10/B10; XG songs get a drum bank on channel 10. See Playing .mid through a VST.

While catching up, only the last SysEx per address and the last CC of each type are applied. A dump that walks all 32 channels several times is collapsed to the latest state at the play position.

Drawing is every 16ms at base; only rows whose picture changed are repainted. When the message queue is idle, notes and ticks are synced extra so short drums still light and bar/beat/tick stay smooth (same for the VST host keyboard). Extra work yields if other apps are busy. A bar when it moves by a pixel, the mini keyboard when held notes change. Even with all 32 parts sounding, the table is not fully repainted.

PC# / BNK / Map / Instrument
Program, bank, GS/XG map, and instrument name (from the built-in SASAMI GS/XG tables).
Lev / Vol / Pan / Exp
Output level plus volume, pan, and expression. The bars are narrow, so the titles use two rows like Vibrato Rat/Dpt, alternating up and down.
Rev / Crs / Var
Reverb, chorus, and variation send amounts.
Vibrato / Filter / Envelope / EQ / NRPN
Live controller / NRPN state for those areas. Headings share the same X as the numbers below.
Keyboard (mini keys on the right)
Keys that are down light up. Short notes stay lit briefly. Click a key to play that part through the current playback path.

Colors

  • Channels that have not yet received a note, CC, or SysEx stay gray. Clicking a mini key to play restores the white / off-white stripe.
  • Drum parts tint the whole row (CH#, name, parameters, and keys) a warm color.
  • A01–B16 light green while sounding, then fade.
  • PC# / BNK / Map keep the row stripe while notes play.
  • An instrument change ambers that cell. Meter bars do not fade.
  • Parts with EFX/insertion show an orange ◆ to the left of the instrument name.

Playing from the mini keyboard and sliders

Clicks on the mini keyboard and drags on volume actually reach the sound, not just the display. During Playing .mid through a VST, they enter the same module as the song. Clicking a key does not rewind the song. When playback uses Windows MIDI, the same output is used. During Adding formats with KPI plug-ins MIDI playback, keys go to the MIDI-out device in Rendering.

View modes (2D / Soft 3D)

  • Normal (2D) — table layout with thin lines between parts; the default.
  • Soft 3D — 32 part levels as boxes, drawn on the CPU only (no OpenGL / Direct3D). Drag to orbit, wheel to zoom, 0 to reset. Switch back to 2D from the right-click menu if it feels heavy.

Timing vs what you hear

When playing through Playing .mid through a VST, note display may lag slightly so it stays close to the audible position (plugin latency and output lead). Until the first note appears, SysEx/CC are not delayed so an opening dump is not dragged by that lag. After the first note, SysEx/CC follow the audible position too.

How it relates to other features

  • Seeing notes on the piano roll — notes over time; the monitor is channel state.
  • Playing .mid through a VST — watch GS/XG VST playback here.
  • Playing instruments with the VST host — live keyboard hosting. Opening the host links its MIDI in and mini keys to this monitor.
  • Controlling the player with a MIDI keyboard — map transport / EQ to hardware.
Tip

Press ? for the in-window guide. See also The “?” guide on every window.

Please note

An audio file such as mp3 does not move the MIDI table or the FM keys. Use the window during SMF, an FM song (.fpy / PMD / FMP), Bonus: old-machine sound, or the VST host keyboard.
